# tools/dotart ─ 原画からドット絵を作る(2026-11 方式)

`tools/PXART_PROCESS.md`(64×96テキストマップ)と `docs/SPRITE_SPEC.md` の変換手順(4×4多数決縮小)に代わる方式。
**状態: 試作(主人公 base / 挙手左 / 挙手右)。出力は `images/px2/`。ゲームが使う `images/px/` は未変更。**

```
python3 tools/dotart/build_hero.py     # 依存: Python3 / numpy / Pillow
```

## 考え方

| 何を | どこから取るか |
|------|----------------|
| 形(輪郭・面・細部) | **承認済みの原画**から。AIの想像で形を作らない |
| 構造(部位・重なり順・関節) | コードで持つ |

1. **ラベル化(`seg.py`)** 原画の各画素を、色ではなく「部位」(輪郭/髪/肌/肌影/スーツ/スーツ影…15種)に分類し、
   ブロック内のラベル多数決で1ドットを決める。色のまま縮小しないので面がまだらにならず、色数は15で固定。
2. **部品化(`part.py`)** 挙手原画から腕(袖+カフ+拳)を、縫い目線と部位ラベルで切り分けて取り出す(矩形で切らない)。
   回転は原画解像度のラベルで行ってからドットへ打ち直す。
3. **リグ(`rig.py`)** 腕を外した胴、部品を置く位置(肩)、重なり順(ラペルと頭は袖より手前)、
   頭の裏に隠れて原画に写っていない袖の下塗りを担当する。寸法は原画への数値フィット。
4. **検証(`build_hero.py`)** 生成結果を挙手原画のラベルと突き合わせ、輪郭一致・部位ラベル一致を毎回表示する。

## 守ること

- **寸法を推測しない。** 腕の太さ・長さ・拳の大きさは原画から測る(最初の試作は推測値で円錐形の腕になり、ラベル一致64%だった)。
- **鏡像にしてよいのは形だけ。光は鏡像にしない。** 光源は右上(PXFEEDBACK R-09、承認済み `px/hero_upR.png` も
  拳のハイライトは右上)。右腕は左腕の鏡像から作るが、拳の内側(ハイライトと影)は入れ替え直す。
- **反転の軸は体の中心。** 脚(下20ドット)の中心を仕様キャンバスの x=80 に合わせてからラベル化する(`seg.fit_frame`)。
- **はみ出しを黙って切らない。** 作業は256幅で行い、`seg.export` は仕様幅に収まらなければ書き出さず必要幅を返す。

## 分かっている限界

- 原画のない角度は、部品を回すだけなので皺や影が応答しない。重要なポーズは原画を足して部品を増やすのが確実。
- 腕を横へ伸ばすポーズは160幅に入らない(必要幅は最大182。`build_hero.py` が角度ごとに表示)。
  キャンバス幅は 2026-07-26 に160で確定済みなので、広げるかどうかは別途決める。
- 矢田・表情差分は未対応。原画ごとに `rig.find_seam` の探索位置など調整が要る。
